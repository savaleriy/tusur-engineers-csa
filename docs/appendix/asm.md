# Ассемблер x86-64 и RISC-V: краткая шпаргалка

Заметка для чтения вывода компилятора, а не для написания больших программ на ассемблере. Здесь собраны команды, которые чаще всего встречаются в `gcc -S` и на Godbolt.

## Синтаксис

У x86-64 два синтаксиса. В AT&T (по умолчанию у GCC) операнды идут в порядке *источник, приемник*, у регистров стоит `%`, у констант `$`:

```asm
movq    $1, %rax
movq    (%rdi), %rax
addq    %rsi, %rax
```

В Intel (флаг `-masm=intel`) порядок *приемник, источник*:

```asm
mov     rax, 1
mov     rax, [rdi]
add     rax, rsi
```

В курсе используем Intel: он ближе к RISC-V и к документации Intel. В Godbolt для x86-64 включите `-masm=intel`.

RISC-V синтаксис один: приемник всегда первый.

```asm
addi    a0, a1, -1
ld      a0, 0(a1)
```

## Регистры

### x86-64

| Регистр | Назначение |
|---|---|
| `rax` | результат функции, аккумулятор |
| `rdi`, `rsi`, `rdx`, `rcx`, `r8`, `r9` | первые шесть аргументов |
| `r10`, `r11` | временные, вызывающий сохраняет сам |
| `rbx`, `r12`-`r15` | сохраняемые вызываемым |
| `rsp` | указатель стека |
| `rbp` | указатель кадра (если включен) |
| `rip` | адрес текущей инструкции |

Младшие части: `eax` (32 бита), `ax` (16), `al`/`ah` (8). Запись в `eax` обнуляет старшие 32 бита `rax`; запись в `ax` или `al` - нет.

### RISC-V

| Регистр | ABI-имя | Назначение |
|---|---|---|
| `x0` | `zero` | всегда 0 |
| `x1` | `ra` | адрес возврата |
| `x2` | `sp` | указатель стека |
| `x5`-`x7` | `t0`-`t2` | временные |
| `x8`-`x9` | `s0`-`s1` | сохраняемые |
| `x10`-`x17` | `a0`-`a7` | аргументы и результат |
| `x18`-`x27` | `s2`-`s11` | сохраняемые |
| `x28`-`x31` | `t3`-`t6` | временные |

`x0` читается как ноль, запись игнорируется. Поэтому `mv a0, a1` - это `addi a0, a1, 0`, а `nop` - `addi x0, x0, 0`.

## Размеры

| Размер | x86-64 | RISC-V |
|---|---|---|
| 1 байт | `byte ptr` | `lb`, `lbu`, `sb` |
| 2 байта | `word ptr` | `lh`, `lhu`, `sh` |
| 4 байта | `dword ptr` | `lw`, `sw` |
| 8 байт | `qword ptr` | `ld`, `sd` |

В AT&T размер задается суффиксом: `movb`, `movw`, `movl`, `movq`. В Intel - `mov byte ptr [rdi], 1`.

## Пересылка и память

| Действие | x86-64 (Intel) | RISC-V |
|---|---|---|
| регистр в регистр | `mov rax, rbx` | `mv a0, a1` |
| константа | `mov rax, 42` | `li a0, 42` |
| адрес метки | `lea rax, [rip+label]` | `la a0, label` |
| чтение | `mov rax, [rdi]` | `lw a0, 0(a1)` |
| запись | `mov [rdi], rax` | `sw a0, 0(a1)` |
| расширение | `movzx`, `movsx` | `lbu`, `lhu`, `lb`, `lh` |
| стек | `push`, `pop` | `addi sp, sp, -N` + `sd`/`ld` |

`lea` вычисляет адрес, но не читает память. Ее же используют для дешевой арифметики: `lea rax, [rdi+rsi*8+24]`.

## Арифметика

| Действие | x86-64 | RISC-V |
|---|---|---|
| сложение | `add rax, rbx` | `add a0, a1, a2` |
| сложение с константой | `add rax, 5` | `addi a0, a1, 5` |
| вычитание | `sub rax, rbx` | `sub a0, a1, a2` |
| умножение | `imul rax, rbx` | `mul a0, a1, a2` |
| деление | `idiv`, `div` | `div`, `divu` |
| остаток | `idiv`/`div` (в `rdx`) | `rem`, `remu` |
| сдвиг влево | `shl rax, 3` | `slli a0, a1, 3` |
| логический сдвиг вправо | `shr rax, 3` | `srli a0, a1, 3` |
| арифметический сдвиг | `sar rax, 3` | `srai a0, a1, 3` |
| побитовые | `and`, `or`, `xor`, `not` | `and`, `or`, `xor`, `xori` |
| сравнение | `cmp rax, rbx` | `slt`, `sltu` + переход |

В x86 `cmp` только выставляет флаги, а переход читает их. В RISC-V флагов нет: `blt a0, a1, label` сравнивает и переходит одной инструкцией.

`div`/`idiv` в x86 делят пару `rdx:rax`; перед делением `rdx` обнуляют (`xor edx, edx`) или заполняют знаком (`cdq`, `cqo`).

## Переходы и вызовы

| Действие | x86-64 | RISC-V |
|---|---|---|
| безусловный переход | `jmp label` | `j label` (`jal zero, label`) |
| равно | `je label` | `beq a0, a1, label` |
| не равно | `jne label` | `bne a0, a1, label` |
| меньше (знаковое) | `jl label` | `blt a0, a1, label` |
| меньше (беззнаковое) | `jb label` | `bltu a0, a1, label` |
| больше или равно | `jge label` | `bge a0, a1, label` |
| вызов | `call func` | `call func` (`auipc` + `jalr`) |
| возврат | `ret` | `ret` (`jalr zero, 0(ra)`) |
| условная пересылка | `cmovz rax, rbx` | нет в базе; `czero.eqz` в Zicond |
| результат сравнения | `sete al` | `slt`, `seqz`, `snez` |

Псевдоинструкции RISC-V: `beqz`, `bnez`, `blez`, `bgez`, `j`, `call`, `ret`, `mv`, `li`, `la`, `not`, `neg`. Ассемблер разворачивает их в настоящие команды.

## Пролог и эпилог

x86-64 с указателем кадра:

```asm
push    rbp
mov     rbp, rsp
sub     rsp, 32
...
leave
ret
```

RISC-V:

```asm
addi    sp, sp, -32
sd      ra, 24(sp)
sd      s0, 16(sp)
...
ld      s0, 16(sp)
ld      ra, 24(sp)
addi    sp, sp, 32
ret
```

`sp` в RISC-V всегда кратен 16 на входе в функцию. В x86 перед `call` стек тоже выравнивают на 16 байт.

## Что искать в выводе компилятора

- `-O0`: переменные живут на стеке, много `mov` между стеком и регистрами.
- `-O2`: счетчики и промежуточные значения в регистрах, циклы упрощены.
- `-O3 -march=native`: появляются `ymm`/`zmm` и `vfmadd` на x86, `v`-инструкции на RISC-V.
- `cmov` вместо `j...` означает, что компилятор убрал ветвление.
- `call` и `ret` в цикле - кандидат на встраивание.
- Длинная цепочка `add`/`imul` с зависимостью по регистру - низкий ILP.

## Godbolt

Для x86-64: компилятор `x86-64 gcc`, флаг `-O2`, при необходимости `-masm=intel`. Для RISC-V: `RISC-V (64-bits) gcc`, флаг `-O2 -march=rv64gc`. `Compile to binary` показывает байты, `Execute` запускает программу.
