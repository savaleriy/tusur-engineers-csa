# 12. Базовые абстрактные типы данных

!!! warning "WIP"
    Материал в работе: текст и задания могут меняться.

Прежде чем оптимизировать структуры под кэш (следующий модуль), полезно руками собрать базовые АТД на C: динамический массив, список, очередь и хеш-таблицу. В C нет сборщика мусора и готовых контейнеров, поэтому придется явно отвечать на вопросы, которые в других языках скрыты: кто владеет памятью, когда вызывать `free`, что происходит при перевыделении и какая цена у каждого обращения к узлу.

## Тип данных и АТД

**Тип данных** - это представление (как устроены байты) плюс операции. **Абстрактный тип данных (АТД)** - это только контракт: какие операции есть и что они обещают, без указания представления.

Например, стек - это АТД с операциями `push`, `pop`, `top`, `empty`. Его можно реализовать на массиве или на списке; пользователь стека не должен знать, как именно.

В C АТД обычно выглядит так:

```c
/* stack.h - интерфейс */
typedef struct stack stack;

stack *stack_new(void);
void   stack_free(stack *s);
int    stack_push(stack *s, int value);   /* 0 - успех */
int    stack_pop(stack *s, int *value);   /* 0 - успех */
int    stack_empty(const stack *s);
```

Структура объявлена неполным типом (`typedef struct stack stack;`): размер и поля скрыты в `.c`. Это дисциплинирует: пользователь не может залезть внутрь и сломать инвариант.

Инвариант - это утверждение, которое всегда истинно. Для динамического массива: `size <= capacity`, для хеш-таблицы: `size <= load_factor * buckets`. Все операции обязаны инвариант сохранять.

## Динамический массив

Самый полезный АТД - массив с автоматическим ростом:

```c
typedef struct {
    int   *data;
    size_t size;      /* сколько элементов */
    size_t capacity;  /* сколько места */
} vec;

void vec_init(vec *v) { v->data = NULL; v->size = v->capacity = 0; }

int vec_push(vec *v, int x) {
    if (v->size == v->capacity) {
        size_t cap = v->capacity ? 2 * v->capacity : 8;
        int *p = realloc(v->data, cap * sizeof *p);
        if (!p) return -1;
        v->data = p;
        v->capacity = cap;
    }
    v->data[v->size++] = x;
    return 0;
}

void vec_free(vec *v) { free(v->data); v->data = NULL; v->size = v->capacity = 0; }
```

Почему рост вдвое, а не на один элемент: при удвоении суммарная работа на $n$ добавлений - $O(n)$, то есть **амортизированно** $O(1)$ на операцию. При росте на константу было бы $O(n^2)$.

Массив хранит элементы подряд - это лучший случай для кэша. Именно поэтому `std::vector` в C++ почти всегда быстрее списка.

## Связный список

Список хранит каждый элемент в отдельном узле:

```c
typedef struct node {
    int value;
    struct node *next;
} node;

typedef struct {
    node *head;
    size_t size;
} list;

int list_push_front(list *l, int x) {
    node *n = malloc(sizeof *n);
    if (!n) return -1;
    n->value = x;
    n->next = l->head;
    l->head = n;
    l->size++;
    return 0;
}
```

Вставка в начало - $O(1)$, но каждый узел выделяется отдельно и лежит в памяти где попало. Обход списка - это **pointer chasing**: каждое следующее обращение может быть промахом кэша. На массиве из $10^6$ элементов сумма обычно в разы быстрее, чем на списке, хотя асимптотика одна.

Список выигрывает, когда нужны вставки и удаления в середине по известному узлу, склейка списков, стабильные итераторы. Для обхода и поиска - почти всегда проигрывает.

## Стек и очередь

**Стек** на динамическом массиве - это `vec_push` и `vec_pop` с конца.

**Очередь** на массиве требует закольцованного буфера, иначе после каждого `pop` пришлось бы сдвигать все элементы:

```c
typedef struct {
    int   *data;
    size_t capacity;   /* степень двойки */
    size_t head;       /* индекс первого */
    size_t size;
} ring;

int ring_push(ring *q, int x) {
    if (q->size == q->capacity) return -1;
    q->data[(q->head + q->size) & (q->capacity - 1)] = x;
    q->size++;
    return 0;
}

int ring_pop(ring *q, int *x) {
    if (!q->size) return -1;
    *x = q->data[q->head];
    q->head = (q->head + 1) & (q->capacity - 1);
    q->size--;
    return 0;
}
```

Степень двойки позволяет заменить `% capacity` на `& (capacity - 1)` - деление дорогое (модуль 2). **Дек** - тот же буфер, но `push`/`pop` с обоих концов.

## Хеш-таблица

Хеш-таблица - это массив корзин; хеш ключа говорит, в какую корзину идти. Простейший вариант - цепочки:

```c
typedef struct entry {
    uint64_t key;
    int      value;
    struct entry *next;
} entry;

typedef struct {
    entry **buckets;
    size_t  nbuckets;
    size_t  size;
} hmap;
```

Вставка и поиск в среднем $O(1)$, но при большом числе коллизий - $O(n)$. Поэтому важен коэффициент заполнения $\alpha = size / nbuckets$: при $\alpha > 0.7$ таблицу перестраивают, увеличивая число корзин вдвое.

Хеш-функция должна быстро перемешивать биты (модуль 17). Для целых чисел часто берут мультипликативный хеш и старшие биты произведения.

Цепочки - учебный вариант; в следующем модуле мы заменим их открытой адресацией, которая лучше лежит в кэше.

## Очередь с приоритетом

Двоичная куча - это массив, в котором дети узла $i$ лежат в $2i+1$ и $2i+2$, а родитель - в $(i-1)/2$. Минимум всегда в корне:

```c
void sift_up(int *a, size_t i) {
    while (i > 0) {
        size_t p = (i - 1) / 2;
        if (a[p] <= a[i]) break;
        int t = a[p]; a[p] = a[i]; a[i] = t;
        i = p;
    }
}
```

`push` - $O(\log n)$, `pop` - $O(\log n)$, построение из массива - $O(n)$. Куча - основа планировщиков, Дейкстры и сортировки heapsort.

## Что дальше

Базовые АТД дают правильность и асимптотику, но не скорость. В следующем модуле мы возьмем те же задачи и разложим данные под кэш: Eytzinger вместо двоичного дерева, B-дерево вместо бинарного поиска, открытую адресацию вместо цепочек, radix sort вместо сравнений.

## Итоги

- АТД - это контракт; представление скрыто за интерфейсом.
- В C владение памятью явное: кто выделил, тот и освобождает.
- Динамический массив дает амортизированно $O(1)$ и лучшую локальность.
- Список хорош для вставок по узлу, плох для обхода из-за pointer chasing.
- Кольцевой буфер превращает очередь в $O(1)$ без сдвигов.
- Хеш-таблица требует контроля коэффициента заполнения и хорошей хеш-функции.
- Двоичная куча дает приоритетную очередь за $O(\log n)$.
