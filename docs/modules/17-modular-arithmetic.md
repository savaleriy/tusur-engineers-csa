# 17. Модульная арифметика и хеширование

!!! warning "WIP"
    Материал в работе: текст и задания могут меняться.

Целые числа в реальных задачах почти никогда не используются "как есть": их складывают по модулю, возводят в степень, хешируют, перемешивают. Здесь много переполнений, битовых трюков и неожиданной математики.

## Арифметика по модулю

Сложение и умножение по модулю $m$ - основа хеширования, криптографии и генераторов случайных чисел.

```c
uint32_t add_mod(uint32_t a, uint32_t b, uint32_t m) {
    return a >= m - b ? a - (m - b) : a + b;
}

uint64_t mul_mod(uint64_t a, uint64_t b, uint64_t m) {
    return (__uint128_t)a * b % m;
}
```

Сложение можно сделать без переполнения, сравнив с $m - b$. Умножение двух 64-битных чисел не помещается в 64 бита, поэтому нужен 128-битный тип (модуль 2) или трюк с разбиением на половины.

Если модуль постоянный, деление можно заменить умножением на магическое число (деление на инвариант и редукция Лемира, модуль 2). Для криптографии используют **умножение Монтгомери**: число хранят в специальном представлении, и деление по модулю заменяется умножением и сдвигом.

## Быстрое возведение в степень

Наивное $a^n$ - это $n$ умножений. Двоичное возведение в степень делает $O(\log n)$ умножений:

```c
uint64_t pow_mod(uint64_t a, uint64_t n, uint64_t m) {
    uint64_t r = 1 % m;
    while (n) {
        if (n & 1) r = (__uint128_t)r * a % m;
        a = (__uint128_t)a * a % m;
        n >>= 1;
    }
    return r;
}
```

Это тот же прием "делить задачу пополам", что и в бинарном поиске. В криптографии $n$ - секрет, и важно, чтобы время не зависело от битов $n$; тогда ветвление `if (n & 1)` заменяют умножением на маску.

### Обратный элемент

Деление по модулю - это умножение на обратный элемент. Обратный $a^{-1}$ существует, только если $\gcd(a, m) = 1$; для простого $m$ и $a \ne 0$ он есть всегда, и по малой теореме Ферма $a^{-1} \equiv a^{m-2} \pmod m$. Для составного $m$ обратный ищут расширенным алгоритмом Евклида.

## Хеширование

Хеш-функция переводит ключ в число, по которому выбирается ячейка таблицы. Хорошая хеш-функция:

- быстрая (несколько умножений и сдвигов);
- хорошо перемешивает биты (лавинный эффект: изменение одного бита меняет половину выходных);
- не дает скоплений на реальных ключах.

**Мультипликативное хеширование** (Fibonacci hashing):

```c
uint64_t hash_u64(uint64_t x) {
    return x * 11400714819323198485ull;   /* 2^64 / phi */
}
```

Старшие биты произведения распределены почти равномерно; младшие - нет, поэтому для индекса берут старшие биты, а не `% 2^k`.

**Полиномиальный хеш** строк:

$$
h(s) = \sum_{i=0}^{n-1} s_i \cdot p^{n-1-i} \bmod m
$$

Он позволяет сравнивать строки за $O(1)$ после предподсчета и искать подстроки; вероятность коллизии мала, если $p$ и $m$ выбраны удачно.

Для хеш-таблиц с открытой адресацией (модуль 13) важна не только функция, но и то, как она раскладывает ключи по линиям кэша.

## Генераторы случайных чисел

`rand()` из libc плох: малый период, плохое распределение, глобальное состояние. Для замеров и симуляций нужен быстрый и качественный ГПСЧ.

**xorshift64**:

```c
uint64_t rng_state = 88172645463325252ull;

uint64_t rng(void) {
    uint64_t x = rng_state;
    x ^= x << 13;
    x ^= x >> 7;
    x ^= x << 17;
    return rng_state = x;
}
```

Он быстрый и проходит простые тесты, но не криптостойкий. Для криптографии нужны ChaCha20 и подобные; для симуляций - PCG или xoshiro, у которых лучше статистика.

Важно: seed и качество ГПСЧ влияют на замеры. Плохой генератор может дать скрытые корреляции и "ускорить" или "замедлить" программу.

## Итоги

- Модульная арифметика требует следить за переполнением; для умножения нужен 128-битный тип.
- Постоянный модуль позволяет заменить деление умножением (Барретт, Лемье, Монтгомери).
- Возведение в степень - $O(\log n)$ умножений.
- Хеш-функция должна быстро перемешивать биты; для индекса берут старшие биты умножения.
- `rand()` не годится для замеров; нужен xorshift/PCG и фиксированный seed.
