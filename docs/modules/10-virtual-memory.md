# 10. Виртуальная память и предвыборка

!!! warning "WIP"
    Материал в работе: текст и задания могут меняться.

Три эффекта, которые объясняют *необъяснимые* провалы производительности: неудачный шаг обращений забивает один набор кэша, каждое обращение к памяти проходит трансляцию адреса, а процессор пытается угадать, что вы прочитаете дальше. Все три можно измерить и использовать.

## Ассоциативность на практике

Номер набора:

$$
set = \left\lfloor \frac{addr}{B} \right\rfloor \bmod S
$$

L1 32 КБ, 8-way, 64 Б: $S = 64$. Адреса с шагом $64 \cdot 64 = 4096$ байт попадают в один набор - и в кэше помещается только 8 из них, хотя кэш почти пуст.

Где встречается: обход матрицы по столбцам, когда длина строки - степень двойки. В эксперименте умножение матриц при $n = 1536 = 2^9 \cdot 3$ примерно в 3 раза медленнее, чем при $n = 1535$.

Лечение: padding (строка длиной 1025 вместо 1024), смена раскладки.

## Виртуальная память

Каждый процесс видит свое адресное пространство. Адрес транслируется в физический через таблицу страниц. Страница обычно 4 КБ.

![Виртуальная и физическая память](../images/virtual-memory.svg#only-light){ width="720" }
![Виртуальная и физическая память](../images/virtual-memory.dark.svg#only-dark){ width="720" }
<figcaption>Виртуальные страницы, таблица страниц и физические страницы. Часть страниц может лежать на диске; обращение к ним вызывает page fault.</figcaption>

x86-64 (4 уровня, 48 бит) и RISC-V Sv48 устроены одинаково:

<figure class="figure" markdown="1">
![Четырёхуровневый обход таблицы страниц](../images/page-walk.svg#only-light){ width="620" }
![Четырёхуровневый обход таблицы страниц](../images/page-walk.dark.svg#only-dark){ width="620" }
<figcaption>Обход таблицы страниц x86-64: по 9 бит адреса на каждый уровень и 12 бит смещения. Каждый уровень - 512 записей по 8 байт, то есть 4 КБ.</figcaption>
</figure>

RISC-V Sv39: 3 уровня по 9 бит + 12 бит смещения.

Полный обход таблицы - до 4 обращений к памяти на одно обращение программы. Именно поэтому нужен TLB: он кэширует готовые трансляции, и тогда обращение к памяти не превращается в четыре.

Виртуальная память заодно решает три задачи: изоляцию процессов, отсутствие внешней фрагментации (страницы не обязаны лежать подряд) и прозрачный доступ к файлам и диску. `mmap` отображает файл в память: чтение страницы подгружает ее лениво, запись возвращается в файл. Swap делает то же в обратную сторону - вытесняет страницы на диск, когда не хватает RAM; программа не падает, но начинает работать в сотни раз медленнее.

## TLB

TLB - кэш трансляций. Порядок величин: L1 dTLB около 64 записей, L2 TLB 1-2 тысячи.

Покрытие TLB:

$$
coverage = N_{entries} \cdot page\_size
$$

$64 \cdot 4 \text{ КБ} = 256$ КБ. С большими страницами 2 МБ: $64 \cdot 2 \text{ МБ} = 128$ МБ.

Большие страницы в Linux:

```c
void *p = aligned_alloc(2 << 20, size);
madvise(p, size, MADV_HUGEPAGE);
```

```bash
cat /sys/kernel/mm/transparent_hugepage/enabled
```

## Page fault

- Minor: страница есть в памяти, нужна только запись в таблицу (первое касание после `malloc`).
- Major: страницу надо читать с диска.

Поэтому первый проход по свежевыделенному массиву медленнее - прогрев в бенчмарках обязателен (модуль 5).

Таблица страниц и TLB тоже влияют на производительность: если рабочий набор не влезает в TLB, каждое обращение может требовать обхода таблицы. Большие страницы (2 МБ или 1 ГБ) уменьшают число записей, и покрытие TLB растет; цена - грубее гранулярность памяти.

## Аппаратная предвыборка

Префетчер замечает шаблон (последовательно, с постоянным шагом) и грузит линии заранее. Работает для массивов, не работает для списков и деревьев, где следующий адрес лежит в данных.

## Программная предвыборка

```c
__builtin_prefetch(addr, 0, 3);   // адрес, 0 - чтение / 1 - запись, локальность 0..3
```

Насколько вперед: чтобы данные успели прийти,

$$
d \approx \left\lceil \frac{L_{mem}}{t_{iter}} \right\rceil
$$

итераций, где $t_{iter}$ - время одной итерации. Слишком рано - линию вытеснят, слишком поздно - не поможет.

Хорошо работает там, где адрес известен заранее, а префетчер его не угадает: обход по индексам `a[idx[i + d]]`, бинарный поиск (модуль 7).

## Итоги

- Конфликты по наборам возникают, когда шаг обращений кратен размеру кэша; лечатся padding и сменой раскладки.
- Виртуальная память добавляет трансляцию адреса, которую ускоряет TLB.
- Page fault - не ошибка, а штатный механизм подгрузки страниц.
- Предвыборка бывает аппаратной и программной; обе обманываются случайным обходом.
