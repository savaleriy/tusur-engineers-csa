## Цель

Написать арифметику по модулю без переполнений, быстрое возведение в степень и хеш-функцию, которую не стыдно положить в таблицу.

## Что сделать

### 1. Арифметика по модулю

```c
uint32_t add_mod(uint32_t a, uint32_t b, uint32_t m);
uint64_t mul_mod(uint64_t a, uint64_t b, uint64_t m);
uint64_t pow_mod(uint64_t a, uint64_t n, uint64_t m);
```

`mul_mod` сделайте двумя способами: через `__uint128_t` и через разбиение на 32-битные половины. Сравните время на $10^8$ вызовов.

### 2. Хеш-функции

Реализуйте:

- мультипликативный хеш `x * 11400714819323198485ull`;
- полиномиальный хеш строки с основанием 131 и модулем $2^{61}-1$;
- простую проверку лавинного эффекта: для 1000 случайных `x` посчитайте, сколько бит выхода меняется при изменении одного бита входа.

### 3. ГПСЧ

Сравните `rand()`, xorshift64 и PCG (или xoshiro):

- скорость на $10^8$ чисел;
- период и качество: постройте гистограмму младших бит, проверьте корреляцию соседних значений.

### 4. Применить

Используйте свой хеш в хеш-таблице из задания 13 и сравните с `% 2^k` и с простым `x * 2654435761`.

## Вопросы

1. Почему `mul_mod` через 128 бит быстрее, чем через половины (или наоборот)?
2. Почему для индекса берут старшие биты произведения, а не младшие?
3. Чем плох `rand()` для замеров?
4. Как проверить, что хеш-функция "хорошо перемешивает"?
