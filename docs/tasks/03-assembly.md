# Задание 3. Чтение ассемблера

> Модуль 3: [Чтение ассемблера: ISA, вызовы и стек](../modules/03-assembly.md). Нужно: Godbolt, ваш код из задания 1. Цели: `x86-64 gcc` и `RISC-V (64-bits) gcc`.

## Цель

Научиться читать вывод компилятора: находить в ассемблере циклы, обращения к памяти, прологи, вызовы и рекурсию. Смотреть будем на ваш код умножения матриц из задания 1 - сначала на `ijk` и `ikj`, потом на Штрассена.

## Что сделать

Ассемблер зависит от версии компилятора и флагов. Сравнивайте только сборки с одинаковыми `gcc`, `-O2` и целевой архитектурой; иначе различие в коде может быть связано не с вашей программой, а с версией компилятора.

### 1. Ваше умножение матриц: `ijk` и `ikj`

Возьмите `matmul.c` из задания 1. Соберите функции `mul_ijk` и `mul_ikj` в Godbolt:

- `x86-64 gcc`, `-O2 -masm=intel`;
- `RISC-V (64-bits) gcc`, `-O2 -march=rv64gc`.

Для каждой версии найдите внутренний цикл и ответьте:

1. Какие инструкции загружают элементы `a`, `b` и `c`?
2. В `ijk` внутренний цикл идет по `k`: как при этом меняется адрес `b[k][j]` - подряд или с шагом в строку?
3. В `ikj` внутренний цикл идет по `j`: что происходит с `b[k][j]` и `c[i][j]`?
4. Сколько инструкций в теле внутреннего цикла у x86-64 и у RISC-V?
5. Появились ли векторные инструкции (`vfmadd`, `ymm`/`zmm` или `v`-код RISC-V) на `-O3 -march=native`?

Объясните, почему `ikj` обходит память лучше, хотя число умножений и сложений у него такое же. Это тот же эффект, который вы мерили в задании 1.

### 2. Штрассен: рекурсия в ассемблере

Возьмите свою реализацию `strassen` из задания 1. Соберите ее с `-O2` и найдите:

- рекурсивные вызовы (`call` на x86-64, `jal`/`jalr` на RISC-V);
- пролог и эпилог функции: сколько байт отрезается от стека и какие регистры сохраняются;
- вызовы `malloc`/`free`, если вы выделяете временные матрицы;
- базовый случай: где заканчивается рекурсия и вызывается обычное умножение.

Ответьте: почему на маленьких матрицах Штрассен может проигрывать, хотя делает меньше умножений? Что в ассемблере соответствует накладным расходам рекурсии?

### 3. Сравните две ISA

Соберите одну и ту же функцию на `x86-64 gcc` и на `RISC-V gcc`:

```c
int max2(int a, int b) {
    return a > b ? a : b;
}

int max3(int a, int b, int c) {
    int m = a > b ? a : b;
    return m > c ? m : c;
}
```

Для каждой ISA найдите:

- где лежат аргументы при вызове и где результат;
- есть ли условный переход (`j...` / `b...`), или компилятор обошелся `cmov` / `slt` и арифметикой;
- сколько инструкций занимает `max3`.

### 4. Прочитайте цикл

Соберите с `-O2` функцию:

```c
long sum(const long *a, long n) {
    long s = 0;
    for (long i = 0; i < n; i++)
        s += a[i];
    return s;
}
```

Найдите в ассемблере RISC-V: пролог, цикл, проверку условия в конце, `ret`. Объясните, почему проверка `n <= 0` стоит до цикла, а переход назад - в конце тела.

### 5. Прочитайте функцию целиком

Соберите в Godbolt:

```c
long f(long n) {
    long s = 0;
    for (long i = 0; i < n; i++) s += i * i;
    return s;
}
```

Найдите в ассемблере пролог (сколько байт отрезано от стека), сохранение `ra`, тело цикла, эпилог и `ret`. Почему размер кадра кратен 16?

## Критерии готовности

- Для `mul_ijk` и `mul_ikj` найден внутренний цикл и объяснены обращения к `b` и `c`.
- Для `strassen` найдены рекурсивные вызовы, пролог/эпилог и базовый случай.
- Для `max2` и `max3` объяснено, где `cmov`, а где переход.
- В `sum` и `f` найдены пролог, цикл, эпилог и `ret`.

## Вопросы

1. Почему в RISC-V нельзя одной инструкцией загрузить значение из памяти и сложить его с регистром, а в x86 можно? Чем за это платит x86?
2. Сравните внутренние циклы `ijk` и `ikj`: какие обращения к `b` идут подряд, а какие с шагом в строку?
3. Как в ассемблере Штрассена видны рекурсивные вызовы и накладные расходы на кадры? Почему на маленьких матрицах это может съесть выигрыш от меньшего числа умножений?
4. Сравните `max2` на x86 и RISC-V: где компилятор обошелся `cmov`/`slt`, а где условным переходом? Почему на x86 ответ может зависеть от компилятора и флагов?
5. Почему программу, собранную для x86-64 в 2005 году, можно запустить на процессоре 2025 года, а собранную с `-march=native` - не всегда?
