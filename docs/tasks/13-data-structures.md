## Цель

Сравнить структуры данных по времени запроса, а не по асимптотике: увидеть, как раскладка в памяти меняет число промахов кэша.

## Что сделать

### 1. Четыре бинарных поиска

Реализуйте поиск `x` в отсортированном массиве:

```c
const int *lb_std(const int *a, int n, int x);        // std::lower_bound
const int *lb_branchless(const int *a, int n, int x); // без переходов
const int *lb_eytzinger(const int *a, int n, int x);  // раскладка Eytzinger
const int *lb_btree(const int *a, int n, int x);      // узел на 16 ключей
```

Для Eytzinger постройте массив из отсортированного: обход в ширину, корень в `a[1]`.

### 2. Измерения

Размеры от $2^{10}$ до $2^{26}$, по $10^6$ случайных запросов. Постройте график "нс на запрос от размера" (логарифмическая шкала). Снимите `cache-misses` и `branch-misses` на запрос для $n = 2^{20}$.

### 3. Хеш-таблица с открытой адресацией

Реализуйте таблицу `uint64_t -> uint32_t` с линейным пробированием:

```c
void put(uint64_t key, uint32_t value);
int  get(uint64_t key, uint32_t *value);   // 1, если найден
```

Сравните с таблицей на цепочках при заполнении 50, 70 и 90%. Измерьте нс на вставку и на поиск.

## Сортировка и графы

1. Сравните `qsort` и radix sort на $10^7$ случайных `uint32_t`: время, число проходов, поведение при разных размерах.
2. Реализуйте сортирующую сеть на 16 элементов через `min`/`max` и сравните с сортировкой вставками.
3. Постройте CSR для случайного графа ($n = 10^6$, $m = 10^7$) и сравните BFS по CSR со списками смежности на указателях: время и `cache-misses`.
