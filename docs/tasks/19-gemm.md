## Цель

Пройти путь от наивного умножения матриц до версии, близкой к пику процессора, и научиться объяснять каждое ускорение цифрами. Это итоговое задание курса: в нем сходятся память, SIMD, ILP и потоки.

## Задача

Умножение квадратных матриц `float`, построчно:

```c
void gemm(int n, const float *a, const float *b, float *c);
```

Этапы:

1. **Память.** Порядок циклов `ikj` или транспонирование `B`, блочность под L1 и L2, выравнивание буферов на 64 байта.
2. **SIMD.** Микроядро: блок `C` размером, например, $6 \times 16$ целиком в регистрах (12 `ymm`), на каждом шаге - broadcast из `A`, две загрузки из `B` и 12 FMA. Упаковка блоков `B` и `A` в непрерывные буферы.
3. **Потоки.** OpenMP по внешнему блочному циклу, график ускорения от числа потоков, оценка доли $f$ по Амдалу.

## Как проверять

1. Корректность на размерах $n = 1, 7, 64, 1000, 1023, 1025, 1920$: относительная ошибка по норме Фробениуса относительно эталона в `double` не больше $10^{-4}$.
2. GFLOPS:

$$
\text{GFLOPS} = \frac{2 n^3}{t \cdot 10^9}
$$

3. Сравните с пиком ядра (формула из модуля 19) и с OpenBLAS:

```bash
OMP_NUM_THREADS=1 ./bench --n 1920
OMP_NUM_THREADS=1 ./bench --n 1920 --openblas
```

4. Для каждого этапа запишите: что сделали, сколько GFLOPS было и стало, какой счетчик `perf` подтверждает причину.

## Roofline

Посчитайте арифметическую интенсивность для $n = 1920$:

$$
I = \frac{2 n^3}{3 n^2 \cdot 4} = \frac{n}{6}
$$

Сравните ее с точкой перегиба roofline (пик / пропускная способность памяти). Объясните, почему наивная версия сидит под наклонной частью, а блочная - под горизонтальной.
