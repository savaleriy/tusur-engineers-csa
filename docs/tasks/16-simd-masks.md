# Задание 16. Маски, перестановки и сбор данных

!!! warning "WIP"

> Модуль 16: [SIMD: маски, перестановки и сбор данных](../modules/16-simd-masks.md). Нужно: x86-64 с AVX2, `gcc -mavx2 -mfma`.

## Цель

Перевести условия на язык масок: сравнение дает маску, маска выбирает между двумя значениями, `movemask` и `popcount` считают, сколько элементов подошло.

## Что сделать

```c
size_t count_lt_i32(const int32_t *a, size_t n, int32_t x);

/* оставить в out элементы a[i] < x, сохранив порядок; вернуть число */
size_t compress_lt(const int32_t *a, size_t n, int32_t x, int32_t *out);

/* индекс минимума через маски */
int32_t argmin_masked(const int32_t *a, size_t n);
```

Начните с скалярных версий. Затем для каждой напишите AVX2-версию:

- сравнение - `_mm256_cmpgt_epi32` (помните про перестановку аргументов);
- `count_lt` - `_mm256_movemask_ps` + `__builtin_popcount`;
- `blend` - `_mm256_blendv_epi8`;
- `compress` - самый интересный: сначала сделайте "в лоб" через скалярное сохранение по маске, затем через перестановки (`_mm256_permutevar8x32_epi32`) и посчитайте, стало ли быстрее.

## Как проверить

1. Массивы длиной 1, 7, 8, 1023, 1024, 1025; порог `x` меньше всех, больше всех и посередине.
2. `compress` не должен терять порядок элементов.
3. Замерьте: скаляр, AVX2 "в лоб", AVX2 с перестановками. Одинаково ли быстро они работают и почему?

## Вопросы

1. Почему после сравнения в AVX2 получается не 0/1, а маска из всех единиц или всех нулей?
2. Чем `blend` отличается от `and`/`or` и когда нужен именно он?
3. Почему `compress` трудно векторизовать и какие подходы существуют?
4. Есть ли на вашей машине AVX-512 и как маски меняют код? Соберите версию с `-mavx512f`, если процессор позволяет.
