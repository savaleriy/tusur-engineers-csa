# Задание 2. Биты без ветвлений

> Модуль 2: [Целые числа и битовые операции](../modules/02-integers.md). Нужно: только Godbolt. Компилятор и запуск - там же. Документация по GCC, Clang и RISC-V - в конце модуля 2.

## Цель

Написать девять функций, в которых нет ни одного `if`, ни одного цикла и ни одного неопределенного поведения, и увидеть, как процессор заменяет ветвление арифметикой и инструкциями.

Правила жесткие: **никаких** `if`, `else`, `?:`, `switch`, `for`, `while`, `do`, `goto` и `__builtin_*`. Сравнения (`x == 0`, `a < b`) разрешены: они дают 0 или 1, а не переход. Логические `&&` и `||` запрещены: они компилируются в переход; используйте побитовые `&` и `|`.

## Что сделать

Напишите в Godbolt (компилятор `x86-64 gcc`) девять функций:

```c
uint32_t bswap32(uint32_t x);       // развернуть порядок байтов
int      is_pow2(uint64_t x);       // 1, если x - степень двойки
uint32_t parity32(uint32_t x);      // 1, если число единиц нечетно
uint32_t popcount32(uint32_t x);    // число единиц
uint32_t ctz32(uint32_t x);         // хвостовые нули, x != 0
uint32_t clz32(uint32_t x);         // ведущие нули, x != 0
uint64_t next_pow2(uint64_t x);     // ближайшая степень двойки сверху
int64_t  sign_extend(uint64_t x, unsigned b);  // b младших бит как int
int32_t  sat_add32(int32_t a, int32_t b);      // сложение с насыщением
```

Условия на границах:

- `is_pow2(0) == 0`, `is_pow2(1) == 1`, `is_pow2(1ull << 63) == 1`;
- `next_pow2(0) == 1`, `next_pow2(8) == 8`, `next_pow2(9) == 16`;
- `sign_extend(0xF, 4) == -1`, `sign_extend(0x7, 4) == 7`, `sign_extend(0x80, 8) == -128`;
- `sat_add32(INT32_MAX, 1) == INT32_MAX`, `sat_add32(INT32_MIN, -1) == INT32_MIN`.

Области определения: `1 <= b <= 64` у `sign_extend`, `x <= 2^63` у `next_pow2`.

## Как проверить

1. Добавьте в тот же файл `main` с проверками: для каждой функции - несколько входов и ожидаемый ответ; при несовпадении печатайте `FAIL` и значения.
2. Запустите программу кнопкой Execute. Все проверки должны пройти.
3. Включите `-O2` и посмотрите на ассемблер: ни в одной функции не должно быть условных переходов (`jne`, `je`, `jl` и т.п.). Вместо них должны быть `sete`, `cmov`, побитовые операции.
4. Повторите сборку с `-march=x86-64-v3` и сравните: у `popcount32`, `clz32`, `ctz32` и `bswap32` должны появиться `popcnt`, `lzcnt`, `tzcnt`, `bswap`. Сколько инструкций осталось в каждой функции?

## Команды и биты

Соберите на Godbolt (x86-64, `-O2`) функции:

```c
unsigned f_and(unsigned x) { return x & 0xff; }
unsigned f_or (unsigned x) { return x | 1; }
unsigned f_shl(unsigned x) { return x << 3; }
int      f_sar(int x)      { return x >> 3; }
unsigned f_xor(unsigned x) { return x ^ (x >> 16); }
```

Для каждой найдите в ассемблере команду (`and`, `or`, `shl`, `sar`, `shr`, `xor`) и объясните, чем `sar` отличается от `shr`. Затем переключитесь на `RISC-V (64-bits) gcc` и найдите те же операции в RISC-V: как они называются там?

## Деление и обмен

Два эксперимента по материалу модуля:

1. Соберите в Godbolt `int d7(int x) { return x / 7; }` и `int m7(int x) { return x % 7; }` при `-O2`. Найдите магическое умножение; замените 7 на переменную - появится `div`.
2. Проверьте обмен трех переменных: XOR-версию и арифметическую. Сравните с обменом через временную переменную: что сгенерировал компилятор в каждом случае?

## Критерии готовности

- Все девять функций проходят проверки.
- Ни в одной функции нет условных переходов при `-O2`.
- Неопределенного поведения нет: проверено санитайзером или рассуждением.
- Для `-march=x86-64-v3` найдены `popcnt`, `lzcnt`, `tzcnt`, `bswap`.
