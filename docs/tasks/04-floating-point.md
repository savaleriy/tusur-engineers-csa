# Задание 4. Плавающая точка и точность

> Модуль 4: [Плавающая точка: IEEE 754](../modules/04-floating-point.md). Нужно: `gcc`, `riscv64-linux-gnu-gcc` (или RISC-V на Godbolt).

## Цель

Увидеть, что числа с плавающей точкой устроены как битовые поля, что порядок сложения меняет результат и что некоторые числа считаются в десятки раз медленнее других.

## Что сделать

### 1. Разобрать float по битам

Напишите функцию, которая печатает знак, порядок и мантиссу:

```c
void print_float(float f) {
    uint32_t u;
    memcpy(&u, &f, sizeof u);       /* законный способ смотреть на биты */
    uint32_t s = /* ... */, e = /* ... */, m = /* ... */;
    printf("%-14g s=%u e=%3u (2^%4d) m=0x%06x\n",
           f, s, e, (int)e - 127, m);
}
```

Проверьте на `1.0f`, `-6.25f`, `0.1f`, `1e-40f`, `1.0f / 0.0f`, `0.0f / 0.0f`. Для каждой строки объясните, что означают поля и почему у последних трех порядок особый.

Почему `memcpy`, а не `*(uint32_t *)&f`?

### 2. Три способа сложить одно и то же

Для $n = 10^7$ посчитайте сумму $S = \sum_{i=1}^{n} 1/i$ четырьмя способами:

- вперед, от $i = 1$ к $n$;
- назад, от $n$ к 1;
- попарно (сумма делится пополам, половинки складываются рекурсивно);
- по алгоритму Кэхэна (компенсированная сумма).

Сравните с точным значением, посчитанным в `double` или `long double`. Выпишите таблицу: способ, результат, относительная ошибка.

### 3. Цена субнормальных чисел

Сравните время двух одинаковых циклов умножения: один работает с числами порядка $10^{-38}$, другой - с числами порядка 1. Сделайте по пять запусков и берите медиану: один замер ничего не доказывает. Затем включите режим FTZ/DAZ (на x86 - через `_mm_setcsr` или флаг компилятора) и повторите.

Почему третий замер может показать 0 секунд, и как этого избежать? (Подсказка: два одинаковых вызова функции с одинаковыми аргументами.)

### 4. FMA и воспроизводимость

Соберите одну и ту же функцию `a * b + c` с `-O2` и с `-O2 -mfma`. Найдите в ассемблере `vfmadd`. Сравните результат для чисел, подобранных так, чтобы округление было заметно (например, `a = 1 + 2^-23`, `b = 1 - 2^-23`, `c = -1`). Совпадают ли ответы двух сборок?

### 5. Три примера: градусы, корень, число e

Ниже - полная программа. Скопируйте ее в `fp_examples.c`, соберите и запустите; отдельно искать код не нужно.

```c
#include <math.h>
#include <stdio.h>

float f2c(float fahr) {
    return (5.0f / 9.0f) * (fahr - 32.0f);
}

void sqrt_demo(int src, float *dst, int *idst) {
    float x = (float)src;
    if (x >= 0.0f)
        x = __builtin_sqrtf(x);
    *dst = x;
    *idst = (int)x;
}

double e_const(double eps) {
    double e = 1.0, term = 1.0;
    for (int n = 1; term >= eps; n++) {
        term /= n;
        e += term;
    }
    return e;
}

long double add_ld(long double a, long double b) {
    return a + b;
}

int main(void) {
    printf("f2c(32)  = %.9g\n", f2c(32.0f));
    printf("f2c(212) = %.9g\n", f2c(212.0f));
    printf("f2c(-40) = %.9g\n", f2c(-40.0f));

    int vals[] = {100, 2, -1};
    for (int i = 0; i < 3; i++) {
        float dst;
        int idst;
        sqrt_demo(vals[i], &dst, &idst);
        printf("sqrt_demo(%d): dst = %.9g, idst = %d\n", vals[i], dst, idst);
    }

    double eps[] = {1e-6, 1e-12, 1e-16};
    for (int i = 0; i < 3; i++)
        printf("e_const(%.0e) = %.17g (M_E = %.17g)\n",
               eps[i], e_const(eps[i]), M_E);

    printf("add_ld(1, 2) = %.21Lg\n", add_ld(1.0L, 2.0L));
    return 0;
}
```

Сборка и запуск:

```bash
gcc -O2 fp_examples.c -lm -o fp_examples
./fp_examples
```

Запишите вывод. Затем соберите ассемблер:

```bash
riscv64-linux-gnu-gcc -O2 -march=rv64gc -S fp_examples.c
```

Для x87:

```bash
gcc -O2 -S -masm=intel fp_examples.c
```

В `fp_examples.s` найдите:

1. В `f2c` - `flw`, `fsub.s`, `fmul.s`. Почему `f2c(212)` может быть не ровно 100?
2. В `sqrt_demo` - `fcvt.s.w`, `fge.s`, `fsqrt.s`, `fcvt.w.s`. Что лежит в `dst` и `idst` для `src = -1`?
3. В `e_const` - `fdiv.d`, `fadd.d`, `fle.d`. Почему при разных `eps` последние биты разные?
4. В `add_ld` - `fld`, `faddp`, `ret`. Зачем x87 стек из восьми регистров и почему его не используют для `float` и `double`?

## Критерии готовности

- Для `print_float` разобраны все шесть значений, включая `1e-40`, бесконечность и NaN.
- Суммы посчитаны четырьмя способами, есть таблица ошибок.
- Субнормальные числа замерены, FTZ/DAZ проверены.
- Программа `fp_examples` собрана, запущена, вывод записан.
- Для `f2c`, `sqrt_demo`, `e_const` и `add_ld` найден ассемблер и объяснены ключевые инструкции.
