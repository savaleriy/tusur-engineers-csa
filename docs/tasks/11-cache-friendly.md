## Цель

Убедиться, что порядок обхода памяти стоит больше, чем арифметика, и научиться выбирать размер блока не на глаз, а из размеров кэшей.

## Что сделать

### 1. Транспонирование

Напишите три версии транспонирования квадратной матрицы `float`:

```c
void transpose_naive(float *dst, const float *src, int n);   /* dst[j*n+i] = src[i*n+j] */
void transpose_block(float *dst, const float *src, int n, int b);
void transpose_rec  (float *dst, const float *src, int n);   /* рекурсивно пополам */
```

Для $n = 4096$ сравните время. Объясните, почему `naive` медленная: посмотрите на шаг обращения к `src` и `dst` и на число промахов.

Подберите размер блока $b$ под L1 и L2 вашей машины. Проверьте, что блоки, подобранные по формуле из модуля, лучше случайных значений.

### 2. Порядок циклов в умножении матриц

Вернитесь к `ijk` и `ikj` из задания 1. Теперь объясните разницу не "на глаз", а через промахи: снимите `cache-misses` для обеих версий и посчитайте, сколько байт из памяти реально прочитано.

### 3. AoS и SoA

Даны структуры:

```c
typedef struct { float x, y, z; } PointAoS;
typedef struct { float *x, *y, *z; } PointsSoA;

float sum_x_aos(const PointAoS *p, size_t n);
float sum_x_soa(const PointsSoA *p, size_t n);
```

Сравните время на $10^7$ точках. Сколько данных читает каждая версия на одну полезную операцию? Что произойдет, если обращаться не к `x`, а по очереди ко всем трем полям?

### 4. Выравнивание

Проверьте `sizeof` и `alignof` для нескольких структур. Затем выровняйте рабочий буфер на 64 байта (`aligned_alloc(64, n)`) и сравните время с невыровненным. Насколько велика разница и когда она исчезает?

## Вопросы

1. Почему `naive` транспонирование медленнее блочного при одинаковом числе операций?
2. Как выбрать размер блока под L1 и L2?
3. Когда AoS лучше SoA и наоборот?
4. Почему выравнивание на 64 байта может ускорить код, а может и не дать ничего?
