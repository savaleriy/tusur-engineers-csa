# Инструменты

Инструменты подключаются по мере надобности, а не все сразу.

- **Модуль 1.** Нужны браузер, Godbolt и Python. Для замеров C в задании 1 удобен локальный `gcc`; без него запускайте C на Godbolt, но время будет шумным.
- **Модуль 2.** Godbolt для ассемблера; локальный `gcc` для санитайзера и замера `popcount`. Если `gcc` нет, сделайте таблицу инструкций и запустите проверки на Godbolt. Готовые примеры к занятию - в папке `examples/` репозитория: `Makefile`, `README.md` и набор C/C++ файлов.
- **С модуля 3.** Чтение ассемблера идет в Godbolt, ставить ничего не нужно.
- **С модуля 4.** Нужен компилятор C на своей машине. QEMU - только если хотите запускать RISC-V или ARM.
- **С модуля 5.** Нужен `perf` и Linux, где доступны аппаратные счетчики.

Ниже - что это за инструменты и как их поставить.

## Godbolt

[Compiler Explorer](https://godbolt.org) - сайт, который компилирует код и показывает ассемблер. Ничего не устанавливает, работает в браузере.

Как пользоваться:

1. Выберите язык (C, C++) и компилятор: `x86-64 gcc`, `RISC-V (64-bits) gcc`, `ARM64 gcc`.
2. В левой панели - код, в правой - ассемблер. Он пересобирается при каждом изменении.
3. Флаги задаются в поле компилятора: `-O2`, `-O3`, `-march=rv64gc`, `-march=skylake`, `-masm=intel`.
4. Кнопка **Execute** (или `Ctrl+Enter`) запускает программу и показывает ее вывод; для этого в коде должна быть функция `main`.

Что Godbolt умеет и чего не умеет:

- Умеет: показать, во что компилятор превратил функцию, сравнить две ISA, сравнить `-O0` и `-O3`, выполнить короткую программу и напечатать результат.
- Не умеет: надежно измерять время. Машина общая, нагрузка неизвестна, поэтому секунды и гигафлопсы с Godbolt - не измерение, а впечатление. Для времени нужен свой компьютер или сервер (модуль 6).

Полезные мелочи:

- `-S` не нужен: Godbolt и так показывает ассемблер.
- Чтобы увидеть байты инструкций, включите в правой панели **Compile to binary** и режим `objdump`.
- Чтобы найти нужную функцию в большом выводе, введите ее имя в поле **Filter**.
- Ссылку на конкретную сборку можно скопировать кнопкой **Share** - удобно присылать вопрос преподавателю.

## Python

Python нужен для быстрых экспериментов и для эталонных вычислений: умножение матриц, суммы, разбор битов, проверка формул.

Откуда взять:

- локально: `python3` в Linux, macOS или WSL2;
- онлайн, если ставить нечего: любой интерпретатор Python в браузере, например [Google Colab](https://colab.research.google.com) или [Python Tutor](https://pythontutor.com).

Что понадобится из стандартной библиотеки и рядом:

| Модуль | Зачем |
|---|---|
| `time`, `time.perf_counter()` | замеры времени |
| `struct` | байты и биты чисел: `pack`, `unpack` |
| `random` | случайные данные для замеров |
| `numpy` | быстрые массивы и эталонное умножение матриц |

`numpy` в Colab уже стоит; локально - `sudo apt install python3-numpy` или `pip install numpy`.

Замеры в Python:

```python
import time

start = time.perf_counter()
# ... работа ...
t = time.perf_counter() - start
print(f"{t:.3f} s")
```

`time.time()` для замеров не годится: он показывает календарное время и может прыгнуть при синхронизации часов. `perf_counter()` монотонен.

## Компилятор C

С модуля 3 нужен `gcc` (или `clang`). Ubuntu и WSL2:

```bash
sudo apt update
sudo apt install build-essential gcc g++ clang llvm make git
```

macOS: `xcode-select --install` или `brew install gcc`.

Основные флаги, которые встретятся:

| Флаг | Что делает |
|---|---|
| `-O0`, `-O1`, `-O2`, `-O3` | уровень оптимизации |
| `-march=native` | разрешить все инструкции текущего процессора |
| `-march=x86-64-v3` | конкретный набор инструкций (здесь: AVX2 и BMI) |
| `-S` | сохранить ассемблер |
| `-g` | отладочная информация для `gdb` и `perf` |
| `-Wall -Wextra` | предупреждения компилятора |

Посмотреть на ассемблер локально:

```bash
gcc -O2 -S prog.c -o prog.s      # AT&T
gcc -O2 -masm=intel -S prog.c -o prog.s
objdump -d --no-show-raw-insn prog
```

## RISC-V и ARM

С модуля 4 нужны кросс-компилятор и эмулятор: на обычном x86-ноутбуке RISC-V код напрямую не запускается.

```bash
sudo apt install gcc-riscv64-linux-gnu qemu-user gdb-multiarch
sudo apt install gcc-aarch64-linux-gnu    # если понадобится ARM
```

Сборка и запуск:

```bash
riscv64-linux-gnu-gcc -static -march=rv64gc -mabi=lp64d prog.c -o prog-rv
qemu-riscv64 ./prog-rv
```

Почему `-static`: без него QEMU нужно указывать, где лежат RISC-V библиотеки (`qemu-riscv64 -L /usr/riscv64-linux-gnu ./prog-rv`).

Почему `-march` указан явно: в свежих Ubuntu кросс-компилятор по умолчанию собирает под профиль RVA23 (векторы, битовые расширения), а не под базовый `rv64gc`. Если нужны векторы - `-march=rv64gcv`, а для QEMU - `-cpu max` (например, `-cpu max,vlen=256`). С `-cpu rv64` даже пустая программа может упасть: `glibc` собрана под более новый профиль.

Отладка под QEMU:

```bash
qemu-riscv64 -g 1234 ./prog-rv          # ждет отладчик на порту 1234
gdb-multiarch ./prog-rv                 # в другом терминале
(gdb) target remote :1234
```

## perf

`perf` - профилировщик Linux. Он показывает время, такты, IPC, промахи кэша и неверные предсказания переходов, а также где именно в программе тратится время.

```bash
perf stat ./prog                                   # время, такты, IPC
perf stat -e cycles,instructions,branch-misses,cache-misses ./prog
perf record -g ./prog && perf report               # профиль по функциям
perf annotate <функция>                            # по строкам и инструкциям
perf list | less                                   # доступные счетчики
```

Для `perf annotate` программу надо собирать с `-g`.

Где `perf` работает не полностью:

- в виртуальной машине и в WSL2 аппаратных счетчиков обычно нет - `perf stat` покажет `<not supported>`;
- в контейнере нужны права на счетчики;
- на сервере может понадобиться `kernel.perf_event_paranoid <= 2`.

Поэтому все замеры делаются на Linux с доступом к счетчикам. Если своего такого окружения нет - работает любой выделенный сервер, а на ноутбуке в VM/WSL2 остаются только таймеры (время, `clock_gettime`).

## Модели и справочники

- `llvm-mca` (входит в `llvm`) - статическая модель планировщика: предсказывает, сколько тактов займет цикл на конкретном ядре.
- [uops.info](https://uops.info) - латентности и пропускная способность инструкций x86.
- [Agner Fog](https://www.agner.org/optimize/) - справочники по оптимизации.
- [ISPC](https://github.com/ispc/ispc) - компилятор SPMD для CPU; альтернатива ручным интринсикам, в курсе пока не используется.

## Проверка окружения

```bash
python3 --version
gcc --version
riscv64-linux-gnu-gcc --version
qemu-riscv64 --version
perf --version
```

Если команда отвечает `command not found`, соответствующий пакет еще не установлен. Это нормально до того модуля, где он понадобится.

## Частые проблемы

| Сообщение | Причина | Что делать |
|---|---|---|
| `Exec format error` | RISC-V бинарник запускают напрямую | `qemu-riscv64 ./prog` |
| `Illegal instruction` | собрано с `-march=native` на другой машине или нет AVX2 | собрать на той машине, где запускаете; проверить `lscpu` |
| `<not supported>` в `perf stat` | нет доступа к счетчикам (VM, WSL2) | работать на машине с Linux и счетчиками |
| `inlining failed ... target specific option mismatch` | интринсики без `-mavx2 -mfma` | добавить флаги |
| `qemu-riscv64: command not found` | не установлен `qemu-user` | `sudo apt install qemu-user` |
| программа на RISC-V падает сразу | `-cpu rv64` со свежей glibc | использовать `-cpu max` или модель по умолчанию |
