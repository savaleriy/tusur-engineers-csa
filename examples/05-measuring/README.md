# Пример к занятию 5: остывание пластины

Код к модулю 5 и заданию 5. Программа `heat` моделирует остывание квадратной пластины из композитного материала и печатает статистику каждые 10 шагов.

Исходная версия не оптимизирована, а один из результатов считается неверно. Найти ошибку, объяснить ее и ускорить программу - часть задания.

Задание: [`docs/tasks/05-profiling.md`](../../docs/tasks/05-profiling.md).
Модуль: [`docs/modules/05-measuring.md`](../../docs/modules/05-measuring.md).

## Быстрый старт

```bash
cd examples/05-measuring
make
./heat --n 512  --steps 100
./heat --n 2048 --steps 200 --out my.txt
```

Сборка вручную, без Makefile:

```bash
gcc -O2 -g heat.c -o heat -lm
```

На машине с Intel i9-13900KF, GCC 16.2.1 и флагами `-O2 -g` быстрый прогон занимает около 0.3 с, полный - около 18 с. Время зависит от процессора, поэтому сравнивайте медиану нескольких запусков, а не один замер.

## Параметры

| Параметр | Значение | По умолчанию |
|---|---|---|
| `--n N` | размер сетки, от 8 до 4096 | 512 |
| `--steps S` | число шагов, от 10 до 100000 | 100 |
| `--out FILE` | записать вывод в файл | стандартный вывод |
| `-h`, `--help` | показать справку | - |

Статистика печатается на шагах, кратных 10. Если число шагов не кратно 10, последняя строка соответствует наибольшему шагу, кратному 10.

## Модель

Пластина - сетка `N x N` ячеек, которая хранится построчно. Каждая ячейка - металл или полимер. Материал задается генератором xorshift32 с фиксированным seed `12345`: `metal[k] = rng & 1`. Материал назначенвсем `N * N` ячейкам, включая граничные: граничная температура фиксирована, но материал граничной ячейки задает коэффициент на границе с соседней внутренней ячейкой.

Границы пластины поддерживаются при нулевой температуре. Внутренние ячейки обновляются явной схемой для уравнения теплопроводности:

```text
T'[i][j] = T[i][j]
    + cn * (T[i-1][j] - T[i][j]) + cs * (T[i+1][j] - T[i][j])
    + cw * (T[i][j-1] - T[i][j]) + ce * (T[i][j+1] - T[i][j])
```

Коэффициент на границе двух ячеек - среднее арифметическое их коэффициентов диффузии:

```text
c = 0.5 * (alpha[i][j] + alpha[сосед])
```

`alpha` равна `0.24` для металла и `0.0024` для полимера. Сумма коэффициентов в узле не превосходит `0.96`, поэтому схема устойчива: новое значение остается выпуклой комбинацией старых, и температура не выходит за пределы начального диапазона.

Начальная температура внутренних ячеек - линейный градиент от 100 улевой границы к 0 у правой:

```text
T[i][j] = 100 * (n - 1 - j) / (n - 1),  1 <= i,j <= n - 2
```

Статистика считается по внутренним ячейкам, граница в нее не входит:

- `total_heat` - сумма температур внутренних ячеек, без множителя на площадь;
- `max_temp` - максимальная температура внутренней ячейки;
- `hist0..hist19` - гистограмма из 20 столбцов шириной 5 градусов:
  `[0,5)`, `[5,10)`, ..., `[90,95)`, `[95,100]`.

Все вычисления детерминированы: при одинаковых `N` и `steps` результат не зависит от запуска.

## Формат вывода

```text
n=2048 steps=200 seed=12345
# step total_heat max_temp hist0..hist19
10 208999293.378076 99.875114 208783 209463 ...
...
200 207556623.050217 99.178352 212413 213087 ...
```

Первая строка - параметры запуска, вторая - заголовок столбцов. В каждой строке статистики: номер шага, полная теплота, максимум и 20 счетчиков гистограммы.

## Контрольные значения

Контрольные значения лежат в файлах:

- [`expected/512x100.txt`](expected/512x100.txt) - прогон `--n 512 --steps 100`;
- [`expected/2048x200.txt`](expected/2048x200.txt) - прогон `--n 2048 --steps 200`.

Последняя строка каждого прогона:

| Прогон | `total_heat` | `max_temp` |
|---|---|---|
| `--n 512 --steps 100` | 12697845.253108 | 98.264938 |
| `--n 2048 --steps 200` | 207556623.050217 | 99.178352 |

Проверка:

```bash
./heat --n 512 --steps 100 --out build/512x100.txt
python3 check.py expected/512x100.txt build/512x100.txt

./heat --n 2048 --steps 200 --out build/2048x200.txt
python3 check.py expected/2048x200.txt build/2048x200.txt
```

`check.py` сравнивает номер шага, полную теплоту, максимум и гистограмму. Допуски: `total_heat` - `1e-6` относительно, `max_temp` - `1e-5` относительно, каждый столбец гистограммы - не больше 5 отсчетов. Такие допуски оставляют место разумным изменениям реализации, но не скрывают грубую ошибку в результате.

Контрольные значения получены для корректной версии с той же физической моделью. Исходная версия проверку не проходит: это ожидаемо и является частью задания.

## Измерения

Счетчики:

```bash
taskset -c 2 perf stat -r 5 \
  -e task-clock,cycles,instructions,branches,branch-misses,\
cache-references,cache-misses,page-faults \
  ./heat --n 2048 --steps 200
```

Профиль:

```bash
perf record -g --call-graph dwarf ./heat --n 2048 --steps 200
perf report --stdio
perf annotate --stdio step
```

Номер ядра в `taskset` зависит от машины. На гибридном Intel P-ядра и E-ядра имеют разные номера и разные счетчики; для сравнения запусков держитесь одного ядра.

## Правила задания

- Физика не меняется: размер сетки, число шагов, формула, коэффициенты,   начальные и граничные условия, определение статистики.
- Можно менять структуры данных, порядок обхода, способ хранения сетки
  и типы.
- Флаги компиляции не меняются. Если нужно поведение, которое обычно дает флаг, его включают в коде и обосновывают.
- Задание про одно ядро: без потоков.

## Команды Makefile

```bash
make          # собрать heat
make check    # прогнать оба размера и сравнить с expected/
make clean    # удалить heat и build/
```

`make check` на исходной версии завершается ошибкой: так и должно быть, пока ошибка в результате не исправлена.
